## 第一部分 · 设计目标与基调

### 1.1 一句话设计目标

> **"打开它,像打开一本会回应你的书。"**

不是"又一个聊天 App"。界面要让用户感到自己进入了一个 **故事空间**,而不是在用一个工具。

### 1.2 三条设计准则

| 准则 | 含义 | 具体要求 |
|---|---|---|
| **内容至上** | 文字是唯一主角 | 聊天页无多余装饰;所有控件默认收起,需要时才浮现 |
| **沉浸优先** | 氛围 > 效率 | 深色为默认主题;留白充足;动效柔和(300ms 以上,ease-out);禁止弹性/夸张动画 |
| **高级感而非卡通** | 目标用户是成人叙事爱好者 | 不用鲜艳撞色、不用卡通吉祥物、不用圆角过大的气泡 |

### 1.3 视觉关键词

`暗色` `墨水` `纸张质感` `暖烛光` `电影感` `克制的金属质感` `衬线标题 + 高可读无衬线正文`

**参考气质**(供设计师找感觉,不是抄):
- Kindle / Apple Books 的阅读专注感
- Arc Browser / Linear 的现代克制感
- 《极乐迪斯科》《80 Days》等叙事游戏的氛围感(但 UI 要更干净)
- 反面案例:普通 IM(微信/Telegram)的功能堆砌气质

### 1.4 设计规格

| 项 | 要求 |
|---|---|
| 平台 | Android,Material 3 为底但需明显的自有气质 |
| 画板 | 360×800 dp(1x),同时出 420dp 宽屏适配说明 |
| 主题 | **深色为主交付**,浅色为次;两套都要出核心页 |
| 动态取色 | 支持 Material You 动态色,但需保证自有色板优先可选 |
| 字体 | 正文:思源黑体 / Inter;标题与角色名:思源宋体 / 衬线体 |
| 暗黑模式对比度 | 正文文字对比度 ≥ 7:1(长阅读场景) |
| 交付物 | Figma 文件,含设计系统(Color/Type/Spacing/Component)、所有页面、关键交互原型、切图资源、图标集 |

## 第二部分 · 信息架构与页面清单

### 2.1 导航结构

```
底部导航(3 个 Tab,不要更多)
├── 「故事」   会话列表(默认页)
├── 「角色」   角色卡库
└── 「我的」   设置 / 模型通道 / 备份 / 调试

全屏独立页(无底部栏)
├── 聊天页        ← 产品 80% 的使用时长在这里
├── 角色卡编辑
├── 模型通道配置
├── 记忆与世界书
├── 存档管理
├── 首次引导流程
└── 调试面板
```

### 2.2 页面清单与设计要点

#### P1 · 首次引导(3~4 屏)+ Key 配置

**这是产品最关键的转化漏斗,请投入最多设计精力。**

- 3 屏价值说明:①它能做什么(放真实对话截图,带状态 HUD 的那种,最有说服力) ②为什么需要你的 Key(坦诚,用图示说明"你的钱付给模型厂商,我们不经手") ③你的数据只在这台手机上(安全感)
- 分叉页:「我已有 API Key」/「我还没有,带我去申请」
- Key 配置页:服务商卡片选择(带 logo)→ 粘贴 Key(支持剪贴板自动识别)→ 大按钮"测试连接"→ 成功/失败的 **明确状态反馈**(失败时必须给出"下一步怎么做")
- "先逛逛"入口:不配 Key 也能看内置角色和一段预录的示例对话

#### P2 · 故事列表(首页)

- 每行:角色头像(圆形/圆角方形)、角色名、最后一句话节选、相对时间、未读/进行中标记
- 若该会话是游戏模式:显示一个极小的状态徽章(如 HP 条缩略)
- 支持:置顶、长按多选、搜索、按角色分组
- 空状态:插画 + "开始你的第一个故事"主按钮

#### P3 · 聊天页(核心页面,请出 5 个以上状态稿)

布局分区:

```
┌──────────────────────────────────┐
│ 顶栏:返回 | 角色名(可点开详情) | ⋮ │  ← 可随滚动隐藏
├──────────────────────────────────┤
│ 状态 HUD(可折叠,游戏模式才有)      │  ← 血条/好感度/地点/物品数
├──────────────────────────────────┤
│                                  │
│   消息流                          │
│   · AI:无气泡或极淡背景的叙事排版   │
│   · 用户:右侧浅色气泡,更紧凑        │
│   · 旁白/系统:居中小字斜体           │
│                                  │
│   (背景:角色立绘低透明度/渐隐)      │
├──────────────────────────────────┤
│ 输入区:[+] [输入框] [发送/停止]     │
└──────────────────────────────────┘
```

必须设计的状态:

1. **正常浏览**
2. **AI 生成中**:打字光标 + "停止"按钮(发送键变形为停止键)+ 顶部细进度条
3. **消息操作态**:长按某条消息 → 浮出操作条(重新生成 / 编辑 / 复制 / 删除 / 从此处分支)
4. **多候选切换(Swipe)**:AI 消息底部有 `‹ 2/3 ›` 指示器,左右滑动切换,要有明确的翻页手势反馈
5. **错误态**:请求失败时的行内错误卡片(红色但不刺眼),带"重试"和"去设置"两个按钮,**用户输入必须还在输入框里**
6. **阅读模式**:全屏、无气泡、小说排版(两端对齐、首行缩进、章节分隔线)、仅一个隐藏的呼出手势
7. **空状态**:仅有角色开场白 + 3 个"你可以试着说..."的引导气泡
8. **编辑消息态**:就地变为可编辑文本域 + 保存/取消

交互细节要求:

- 输入框 `+` 展开:导演指令(OOC)、掷骰、插入旁白、上传图片(P3)
- 用户上滑浏览历史时,右下出现"↓ 回到底部"悬浮按钮
- 状态变化动效:HP 减少时数字旁飘出 `-12` 红字并上浮淡出;获得物品时 HUD 物品图标轻微弹跳
- `*动作*` 渲染为斜体 + 稍暗色;`"对话"` 渲染为高亮色;其余为叙述色。**这三层文字的色阶需要设计师明确定义**

#### P4 · 角色库

- 网格卡片(2 列):立绘/头像为主视觉,底部渐变遮罩压角色名 + 标签
- 顶部:搜索 + 标签筛选 chips
- 右下 FAB:新建角色 / 导入角色卡(两个选项)
- 卡片长按:编辑 / 复制 / 导出 / 删除

#### P5 · 角色卡编辑

字段多,必须分组折叠,避免"一屏 20 个输入框"的恐怖感:

```
▸ 基础   头像、名称、标签、简介
▸ 人设   人物设定(大文本域,显示字数+token数)、说话风格
▸ 开场   场景设定、开场白(支持多条备选)
▸ 示例对话  可增删的对话对列表(强调"这项对风格影响最大")
▸ 游戏规则  状态字段定义(数值/开关/物品/好感度)、初始值、上下限  ← 需要一个清晰的"字段编辑器"组件
▸ 高级   绑定世界书、专属 Prompt 覆盖
```

- 每个大文本域右下角显示 **token 计数**,超过建议值时变黄提示
- 顶部常驻"预览"按钮:直接用当前配置开一个临时会话试聊

#### P6 · 模型通道配置

- 通道列表:名称、服务商图标、当前模型、连接状态小圆点(绿/灰/红)
- 新增/编辑表单:服务商模板选择 → Base URL → API Key(默认遮蔽,带眼睛图标)→ 模型(可拉取下拉 / 手动输入)→ 采样参数(三档预设 + 展开高级滑块)
- **「测试连接」按钮是这一页的主角**,状态反馈要大而明确
- 底部:本月 token 用量与估算费用(纯本地统计)

#### P7 · 记忆与世界书

- Tab 切换:记忆条目 / 世界书
- 记忆条目:时间线样式卡片列表,每条可编辑/置顶/删除,显示"覆盖第 12-34 轮"
- 世界书:条目列表(关键词 chips + 内容节选),可开关启用
- 顶部:本会话上下文占用的可视化条形图(各块占比,颜色区分)—— **这个组件既实用又很有"专业感",是产品的视觉亮点之一**

#### P8 · 存档管理

- 卡片列表:时间、轮次、状态摘要快照(HP/地点)、可选的截图缩略
- 操作:读取(带二次确认)、重命名、删除
- 顶部"立即存档"按钮

#### P9 · 设置 / 我的

分组列表:外观(主题/字体/字号/气泡样式/阅读模式)、模型通道、记忆与压缩、Prompt 预设、备份与导出、隐私与安全(PIN/内容分级/清空数据)、开发者选项(调试面板)、关于

#### P10 · 调试面板(面向高级用户,可以"技术感"一些)

- 本轮请求的块级分解:每块的名称、token 数、是否被裁剪(折叠展开看全文)
- 原始请求体 JSON(Key 已脱敏)+ "复制为 curl"
- 最近请求列表:耗时、token、状态码
- 风格允许偏向等宽字体 / 终端感,与主界面形成有意的对比

## 第三部分 · 设计系统要求

### 3.1 色彩(请设计师在此框架内定稿)

| 语义 | 深色模式方向 | 用途 |
|---|---|---|
| 背景 Base | 接近纯黑但偏暖的深灰(非 #000) | 长阅读不刺眼 |
| 表面 Surface | 比背景略亮的层级(至少 3 层) | 卡片、输入区、HUD |
| 主色 Accent | **暖金 / 琥珀色** | 关键按钮、角色名、进度 |
| 次色 | 低饱和青或紫 | 用户气泡、链接 |
| 叙述文字 | 高对比暖白 | AI 叙事正文 |
| 对话文字 | 比叙述略亮或带主色倾向 | 引号内台词 |
| 动作文字 | 比叙述暗 15~20% + 斜体 | `*星号包裹*` 的动作 |
| 语义色 | 成功/警告/错误/信息 | 需在暗色下依然柔和,不要荧光红 |

**必须交付**:文字三层色阶在真实段落中的对比示例图。这是本产品最独特的排版问题。

### 3.2 字体阶梯

| 用途 | 要求 |
|---|---|
| 角色名 / 标题 | 衬线体,营造书卷感 |
| 叙事正文 | 无衬线,16sp 默认,行高 1.7~1.8(长文阅读) |
| 用户输入 | 15sp |
| 元信息 | 12sp,低对比 |
| 调试面板 | 等宽 13sp |

用户可调字号(5 档),设计需保证最大档不破版。

### 3.3 组件清单(需出规范)

气泡(AI/用户/系统)、消息操作浮条、Swipe 指示器、状态 HUD(血条/好感度条/物品格)、token 占用条形图、字段编辑器、服务商卡片、连接状态指示、折叠分组、空状态组、行内错误卡、FAB 组、底部弹层、二次确认对话框、Toast/Snackbar、加载骨架屏

### 3.4 动效规范

| 场景 | 要求 |
|---|---|
| 页面转场 | 共享元素(角色头像 → 聊天页顶栏),280ms ease-out |
| 消息出现 | 淡入 + 轻微上移 8dp,不要缩放 |
| 流式文字 | 无动画,仅光标闪烁(避免与真实流速冲突) |
| 状态变化 | 数值飘字上浮 600ms + HUD 条平滑过渡 400ms |
| 长按呼出 | 轻触觉反馈 + 浮条 180ms 弹出 |
| 禁止 | 弹跳(bounce)、旋转、超过 500ms 的转场、任何闪烁 |

### 3.5 无障碍

- 所有可点区域 ≥ 48dp
- 完整 contentDescription
- 支持系统字体缩放至 200% 不破版
- 不以颜色作为唯一信息载体(状态变化同时给文字/图标)

## 第四部分 · 交付给设计师的提示词

> 以下内容可以整段复制给设计师(或用于 AI 设计工具)。

### 【设计委托 · Mirage 幻境 AI 互动叙事 App】

**产品是什么**
一款 Android 应用,用户导入或创建一个 AI 角色,然后与它进行长篇的角色扮演、情景模拟和文字冒险游戏。用户使用自己的 AI 服务密钥,所有数据保存在本地。核心使用场景是:**用户在夜晚,长时间、沉浸式地阅读和书写一个由 AI 共同创作的故事。**

**目标用户**
25-40 岁的叙事内容爱好者与轻度技术玩家。他们读小说、玩文字冒险游戏、懂一点 AI。他们反感幼稚化和过度营销的界面,欣赏克制、专业、有质感的设计。

**设计目标(一句话)**
"打开它,像打开一本会回应你的书。"要让人感到进入了一个故事空间,而不是在用一个聊天工具。

**视觉基调**
- 关键词:暗色、墨水、纸张质感、暖烛光、电影感、克制
- 默认深色主题(偏暖的深灰背景,非纯黑),主色为暖金/琥珀色,整体低饱和
- 标题与角色名用衬线体营造书卷气,正文用高可读性无衬线体,行高宽松(1.7 以上)
- 气质参考:Kindle 的阅读专注感 + Linear/Arc 的现代克制感 + 叙事游戏的氛围感
- **明确避免**:普通即时通讯软件的气质、鲜艳撞色、卡通插画、大圆角糖果气泡、拟物化过度、夸张动效

**最重要的一件事:聊天页的文字排版**
这是产品的灵魂页面,用户 80% 时间在这里。AI 的回复不是普通聊天气泡,而是 **小说式的叙事段落**,其中包含三种语义不同的文字,需要你设计出清晰但和谐的三层视觉层次:
1. 叙述(环境、动作描写)—— 基准色,正常字重
2. 角色台词(引号内)—— 更亮或带主色倾向,略强调
3. 角色动作(星号包裹,如 `*她转过身*`)—— 斜体,比基准色更暗
请提供真实段落的排版示例图,这是本次设计的核心产出之一。

**需要设计的页面(按优先级)**
1. 聊天页(核心,需 8 个状态:正常 / 生成中带停止按钮 / 消息长按操作 / 多候选左右切换 / 错误重试 / 全屏阅读模式 / 空状态 / 消息编辑中)
2. 首次引导流程(3 屏价值说明 + 密钥配置页 + 连接测试的成功失败反馈)—— 这是转化漏斗关键
3. 故事列表(首页)
4. 角色库(网格卡片)
5. 角色卡编辑(字段很多,需要优秀的分组折叠方案,含一个"游戏状态字段编辑器"组件)
6. 模型通道配置(表单 + 连接状态反馈 + 用量统计)
7. 记忆与世界书(含一个"上下文占用可视化条形图"组件)
8. 存档管理
9. 设置页
10. 调试面板(允许偏技术感/等宽字体,与主界面形成有意对比)

**游戏化元素**
部分故事带数值玩法,聊天页顶部有一个可折叠的状态面板(HUD),显示生命值条、好感度、当前地点、物品数量。数值变化时需要有克制但有爽感的反馈(如数字旁飘出 `-12` 并上浮淡出)。请设计这个 HUD 的展开态与折叠态。

**交付要求**
- Figma 源文件,含完整设计系统:色彩 token(语义化命名,深浅两套)、字体阶梯、间距规范、圆角与阴影规范、完整组件库(含各状态)
- 画板 360×800dp,并说明宽屏(420dp+)适配策略
- 深色模式为主要交付,浅色模式至少覆盖核心 5 页
- 关键流程可交互原型:首次引导全流程、一次完整对话(含生成中/切换候选/错误重试)
- 动效说明:时长、曲线、触发条件。整体要求柔和(280-400ms,ease-out),严禁弹跳与闪烁
- 图标:统一风格的线性图标集(约 40 个),2px 线宽级别
- 无障碍:正文对比度 ≥ 7:1,可点区域 ≥ 48dp,支持 200% 字体缩放

**约束**
- 遵循 Material 3 的交互规范与控件行为,但视觉上必须有明确的自有识别度,不要做成"默认 M3 的样子"
- 所有内容区域要考虑"文字可能非常长"(单条 AI 回复可达 1000 字以上)
- 考虑用户可自定义字号(5 档),最大档不能破版

## 第五部分 · 设计评审检查清单

设计稿回来后,按此清单验收:

- [ ] 聊天页的三层文字色阶在真实长段落中是否清晰且不疲劳?(请在手机上实机看,不要只看电脑屏)
- [ ] 深色模式下连续阅读 10 分钟是否刺眼?
- [ ] "生成中"状态用户是否能一眼找到停止按钮?
- [ ] 错误态是否明确告知了用户"下一步做什么"?
- [ ] 多候选 Swipe 的指示器是否足够明显,用户能发现这个功能吗?
- [ ] Key 配置页是否让人感到安全可信,而不是在骗取密钥?
- [ ] 角色卡编辑页字段很多,首屏是否仍然"看起来简单"?
- [ ] 状态 HUD 在不玩游戏的会话里是否完全隐形,不打扰?
- [ ] 最大字号档位下所有页面是否不破版?
- [ ] 所有空状态、加载态、错误态是否都有设计,而不只有理想态?

## 🆕 第八轮 E1 补充:状态面板的美术难题(2026-10-19,`MVU的UI页.png`)

### 1. 竞品面板实际长什么样

`MVU的UI页.png` 里的面板**不是一张通用数据表**,而是**卡片作者定制的整套美术**:

### 2. 🔴 这对 `ADR-011`(原生渲染)是一个真实挑战

> `ADR-011` 已拍板:**面板原生 Compose 渲染,不执行卡内 JS。**安全性上无可争议。
> 但这张截图暴露了代价:**原生渲染会丢掉卡片作者的美术表达。**
> 上面那套「幕次 / 字距 / 配色 / 点阵水壶 / 空槽 / 页脚引语」**全是作者的叙事设计**,
> 不是通用控件能还原的。而角色卡的**美术质感恰恰是 DZMM 的核心优势**(`docs/11 §2.4`)。

**→ 建议(不推翻 `ADR-011`,而是给它补一层):主题化槽位(Themed Slots)**

| 做法 | 说明 |
|---|---|
| **控件由我们定,皮肤由卡片定** | 卡片只能从**我们提供的控件集**里选(进度条/数值对/徽章/点阵/标签/空槽/引语),但可以声明**主题变量**:主色、底色、描边、字体族(衬线/无衬线)、圆角、字距 |
| **布局用声明式槽位,不用 HTML/CSS** | 卡片写 `{"slot":"header","style":"ceremonial","text":"第三幕"}` 这类**受限 DSL**,由 Compose 解释渲染。**无 JS、无任意 CSS、无网络资源** |
| **给 3~5 套内置主题兜底** | 没声明主题的卡片走默认主题,不至于全部长一个样。主题名如「暗黑奇幻」「现代都市」「清新日常」 |
| **点阵/空槽这类表达要内置** | `●●●●○ 4/5` 比 `4/5` 直观得多;`行囊[空]` 的虚线空槽比「无」有代入感。**这些是低成本高感知的细节,务必做进控件集** |

> ⚠️ **这不是 MVP 范围**。v1 先用默认主题把数据显示对(`A-19` 模板编辑器 P1);
> 主题化槽位列为 **P2**,但**数据结构从一开始就要留出 `theme` 字段**,否则后面改不动。

### 3. 给设计师的提示词增补

> 在原提示词基础上追加:
>
> 「**状态面板**需要两套视觉:**① 默认主题** —— 克制、中性、与聊天界面同一套设计语言,
> 保证任何角色卡都不难看;**② 主题化示例 ≥3 套** —— 证明同一套控件(进度条、数值对、
> 徽章、点阵计数、标签、空槽、页脚引语)在不同主色/字体族/描边下能呈现完全不同的气质,
> 例如『暗黑奇幻(深酒红+金+衬线)』『现代都市(冷灰+青+无衬线)』『清新日常(米白+暖橙+圆体)』。
> 请明确标出哪些是**可被角色卡覆盖的主题变量**(主色/底色/描边/字体族/圆角/字距),
> 哪些是**固定不可改的结构**(控件形态、间距栅格、无障碍对比度下限)。」
>
> 另追加:**结算状态条的四态视觉**(见 `docs/13` / `docs/15 §7.10.3`)——
> 结算中(中性+加载)/ 已更新·N项(成功色,可展开逐字段 `旧值 → 新值`)/
> 本轮无变化(中性,**明确不是错误**)/ 更新失败·N项(错误色 + 描边 + 原因文本 + 重试按钮)。
> **四态必须一眼可辨,且「无变化」绝不能看起来像出错。**
