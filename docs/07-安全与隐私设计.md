## 1. API Key 安全(当前阶段的最高优先级)

用户把自己的付费凭证交给你,这是极高的信任。**一次 Key 泄露事件足以终结这个产品**,即使它只在小范围分发。

### 1.1 五条铁律

| # | 规则 | 实现 |
|---|---|---|
| 1 | **加密存储** | Android Keystore 生成主密钥(StrongBox 优先)→ Tink AEAD 加密 → 密文存 Room。KMP 下通过 `SecureKeyStore` 接口 + `actual` 实现 |
| 2 | **永不入日志** | 全局日志拦截器,正则脱敏 `sk-[A-Za-z0-9_\-]{8,}` → `sk-***`;同时脱敏 `Authorization` 头与整个请求体 |
| 3 | **永不出端** | 除用户配置的 Base URL 外,App **不向任何其他域名发送请求**。包括崩溃上报与统计 |
| 4 | **备份默认不含 Key** | 用户显式勾选时,用其设定密码 PBKDF2(≥10 万次迭代)派生密钥后 AES-GCM 加密 |
| 5 | **禁止系统备份** | `allowBackup="false"`,主密钥材料放 `no_backup/` |

### 1.2 ⚠️ 第 6 条铁律(2026-10-16 真实事件后补充)

| # | 规则 | 说明 |
|---|---|---|
| **6** | **Key 绝不出现在人工整理的文档、截图、PDF、聊天记录中** | 上述 5 条全是**工程侧**防线。实测阶段真实发生的泄露,走的是**第 4 个通道:开发者自己整理的测试记录文档**(`docs/14 §0`)。工程防线再严也挡不住人手工复制 curl |

**这次事件的教训,比条文本身更重要:**

| 教训 | 说明 |
|---|---|
| ① **"掩码一处"等于没掩码** | 本次 PDF 首页把 Key 掩码成 `sk-cb38265*****`,但正文 11 处 curl 全是完整明文。只要有一处漏网,掩码就白做了 |
| ② **正确做法是"根本不出现"** | 文档里**整行删掉** `-H "Authorization: ..."`,而不是写掩码版 |
| ③ **流程比自觉可靠** | 脱敏必须是**脚本化的一步**(`docs/14 §7.3` 的 `sed` 管道),不能靠"记得手动改" |
| ④ **泄露后只有一个有效动作:吊销** | 不是"删掉文件",是**到平台后台 revoke 并重建**。文件一旦发出去就不可收回 |

> **这条铁律同样适用于将来的用户支持场景:** 当用户发诊断包/截图给我们排查问题时,
> **诊断包导出功能(`docs/02 §5.12`)必须在导出时就脱敏**,不能指望用户自己处理。

### 1.2 额外措施

- 内存中不长期持有明文 Key:构造请求头时解密,用完即弃
- 调试面板展示请求体时,Authorization 显示为 `Bearer sk-****abcd`(仅保留后 4 位)
- Key 输入页设置 `FLAG_SECURE`(防截屏/防录屏,对信任感有帮助)
- 粘贴 Key 后提示"建议清空剪贴板",并提供一键清空
- **依赖审计**:每个三方库都要确认其不做网络请求。引入任何新库前问一句"它会不会偷偷联网";定期 `./gradlew :androidApp:dependencies` 审查传递依赖
- App 内明确告知:**建议使用有额度上限的专用 Key**,不要用无限制的主账号 Key

### 1.3 网络安全配置

```xml
<!-- network_security_config.xml -->
<network-security-config>
    <base-config cleartextTrafficPermitted="false" />
    <!-- 允许用户配置本地模型(Ollama / LM Studio)时的明文 -->
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="false">localhost</domain>
        <domain includeSubdomains="false">127.0.0.1</domain>
        <domain includeSubdomains="true">192.168.0.0</domain>
    </domain-config>
</network-security-config>
```

> 用户配置 `http://` 的非本地地址时,必须弹明确警告:"该地址未加密,你的 API Key 可能被窃听"。

### 1.4 KMP 下的注意点

| 项 | 说明 |
|---|---|
| `SecureKeyStore` 是 expect/actual | 接口在 commonMain,Android 用 Keystore+Tink;iOS(预留)用 Keychain |
| **共享层不得出现明文 Key 的持久化** | 加解密只在平台实现中发生,commonMain 只经手"调用时的瞬时明文" |
| 日志脱敏放 commonMain | 保证将来 iOS 侧自动享有同样保护 |
| Ktor 日志插件 **默认关闭** | `Logging` 插件会打印完整请求头。若开启,必须配置 `sanitizeHeader { it == "Authorization" }` |

> ⚠️ **Ktor 的 `Logging` 插件是本项目最容易泄露 Key 的地方。** 建议直接不装该插件,改用自己的脱敏日志拦截器。

## 2. 隐私工程

### 2.1 数据清单

| 数据 | 存储位置 | 是否离开设备 | 用途 |
|---|---|---|---|
| API Key | 本机加密存储 | **否**(仅作为鉴权头发往用户配置的服务商) | 调用模型 |
| 对话内容 | 本机数据库 | **否**(仅发往用户配置的服务商) | 生成回复 |
| 角色卡 / 记忆 / 存档 | 本机 | 否 | — |
| 设置 | 本机 | 否 | — |
| 崩溃日志 | 本机 | **默认否**;用户主动点"上报"时才发送(已脱敏) | 修 Bug |
| 匿名使用统计 | — | **默认关闭(opt-in)**;当前阶段建议直接不做 | — |

### 2.2 必须在产品中明示的一句话

> "你的对话内容会发送给**你所配置的** AI 服务商以生成回复,其处理方式遵循该服务商的隐私政策。除此之外,你的数据不会离开这台设备。"

出现位置:首次引导第 3 屏、Key 配置页底部、关于页。

### 2.3 权限清单(越少越好)

| 权限 | 是否必需 | 说明 |
|---|---|---|
| `INTERNET` | 必需 | 调模型 API |
| `ACCESS_NETWORK_STATE` | 必需 | 网络状态提示 |
| 读取图片(SAF) | 必需 | 导入头像/角色卡,**用 SAF 而非 READ_EXTERNAL_STORAGE** |
| 写入文件(SAF) | 必需 | 导出备份 |
| `RECORD_AUDIO` | 可选 | 仅语音输入(P3),运行时申请 |
| `POST_NOTIFICATIONS` | 可选 | 后台生成完成提醒 |

**不要申请**:位置、通讯录、电话、相机(除非做头像拍照)、后台常驻。

### 2.4 数据丢失才是当前最现实的"隐私事故"

无服务端 + 不发布 = 用户的全部数据在一台手机上,没有任何兜底。

| 措施 | 优先级 |
|---|---|
| 全量备份导出/导入(H-1/H-2) | **P0,MVP 必须有** |
| 首次使用 7 天后主动提醒"导出一次备份" | P1 |
| Room 迁移前自动本地快照(保留最近 2 份) | **P0** |
| 一键清空数据需二次确认 + 输入确认词 | P1 |

## 3. 代码安全

| 项 | 措施 |
|---|---|
| 混淆 | R8 开启;注意 kotlinx.serialization 的 `@Serializable` 类需 keep 规则;Koin 反射部分需验证 |
| 反调试 / 完整性校验 | **不做**。对本产品无意义,且会误伤正常用户、妨碍将来开源 |
| 依赖漏洞扫描 | CI 中加入依赖检查任务(低成本,顺手做) |
| **是否开源** | **建议认真考虑**。对 BYOK 工具,开源是建立"我们真的没偷你的 Key"信任的最强手段,也最受目标用户认可。当前既然不打算商店发布,**开源 + GitHub Release 直接分发 APK** 反而是最自然的路径 |

## 4. 将来若要公开发布时再处理(当前不投入)

> 本节仅作备忘。**当前阶段不需要做任何事。**

### 4.1 届时需要补的东西

| 项 | 说明 |
|---|---|
| 隐私政策 + 用户协议 | 可托管在 GitHub Pages(免费) |
| 内容分级设置 + 年龄确认 | 商店审核要求 |
| AI 生成内容标识 | 多数平台的要求 |
| 免责声明 | 虚构内容;不构成医疗/法律/心理建议 |
| 商店素材 | 截图、描述。定位统一表述为"**互动叙事 / 文字冒险**" |
| 数据安全表单 | 可诚实勾选"不收集任何数据" —— 这是优势,值得在描述里强调 |
| 应用描述需前置说明"需自备 API Key" | 避免因此产生的差评与退款 |

### 4.2 已排除的事项(不再考虑)

- ~~国内应用商店上架~~
- ~~工信部 App 备案~~
- ~~国内法律咨询~~
- ~~本地敏感词过滤 / 国内版 productFlavor~~
- ~~生成式 AI 服务备案 / 算法备案~~(BYOK 下本就不适用)

### 4.3 无论是否发布都应坚持的自我约束

这几条与合规无关,是产品定位问题,**现在就要守住**:

- ❌ **不内置任何违规角色卡**。内置示例必须绝对安全(冒险、推理、历史、职场模拟)
- ❌ **不提供"越狱 Prompt"预设**。不内置、不推荐、不在文档里教。一旦做了,产品性质就从"工具"变成"规避审核的工具",将来任何发布可能性都会关闭
- ❌ **不做内容社区 / 角色卡市场**。一旦有 UGC 分发,就成了内容平台,合规负担瞬间回到最重档位
- ✅ 角色卡分享只做"导出文件 / PNG,用户自己传",**不做任何服务端中转或聚合展示**

## 5. 当前阶段的分发方式

既然不走应用商店:

| 方式 | 说明 |
|---|---|
| **直接安装 APK** | 自用 + 给朋友测试,最简单 |
| **GitHub Release** | 封闭测试阶段的首选:有版本管理、有更新日志、用户可自助下载 |
| Firebase App Distribution(可选) | 若需要管理测试者名单与崩溃收集。**注意**:会引入 Firebase SDK,与"不联网"卖点冲突,建议仅用于 debug 构建变体 |
| F-Droid(若开源) | 将来的一个无需商店审核的分发渠道 |

**建议**:M5 封闭测试直接用 GitHub Release + 一个 Issue 模板收集反馈。零成本、零合规负担。

## 6. 当前阶段安全检查清单

发给第一批测试用户前必须确认:

- [ ] `adb logcat` 全程搜不到 Key 明文(含 `sk-`、`Bearer`、完整请求体)
- [ ] Room 中 `api_key_cipher` 字段确为密文(直接 dump db 验证)
- [ ] Ktor `Logging` 插件未启用,或已配置 header 脱敏
- [ ] `allowBackup="false"` 已配置
- [ ] 导出的备份文件中搜不到 Key
- [ ] 抓包确认:App 除用户配置的 Base URL 外无任何其他网络请求
- [ ] 依赖清单审查:无可疑的联网库
- [ ] 清空数据功能确实清空(含加密主密钥)
