# 10 · AI 术语速查表(给 Android 开发者)

> 按"你会在什么时候遇到它"排序,不按字母排序。每条都附上"对本项目意味着什么"。

---

## 一、调 API 时立刻会遇到的

### Token(令牌)
模型处理文本的最小单位。不是字,也不是字符。
- 英文:约 4 个字符 = 1 token
- 中文:约 1~1.5 个字 = 1 token
- **对本项目**:计费单位、上下文长度单位。`docs/02` §5.4 讲了怎么算。

### Context Window(上下文窗口)
一次请求中"系统提示 + 对话历史 + 本轮输入 + 预留输出"的 token 总上限。常见 8K / 32K / 128K / 200K。
- **对本项目**:超限会直接报错。这是记忆系统存在的全部理由。

### Prompt(提示词)
发给模型的全部输入内容。
- **System Prompt**:角色与规则的定义,优先级最高
- **User Prompt**:用户这一轮说的话

### messages 数组
OpenAI 风格 API 的核心结构:`[{role: "system"|"user"|"assistant", content: "..."}]`。
- **对本项目**:`ContextBuilder` 的全部工作就是生产这个数组。

### Streaming / SSE(流式输出)
模型逐片段返回内容,用 Server-Sent Events 协议,每行 `data: {...}`,以 `data: [DONE]` 结束。
- **对本项目**:必须实现,否则用户要盯着空屏等 30 秒。`docs/02` §5.2。

### temperature(温度)
采样随机性。0 = 几乎确定性输出;1.0+ = 更有创意也更易崩。
- **对本项目**:角色扮演用 0.8~1.0。

### top_p(核采样)
另一种随机性控制:只从累计概率 top_p 的候选词里选。
- 一般与 temperature 二选一调,本项目默认 0.95。

### presence_penalty / frequency_penalty(重复惩罚)
降低已出现词的概率,减少复读。
- **对本项目**:角色扮演的复读问题主要靠它 + Prompt 解决。注意部分服务商不支持,传了会 400。

### max_tokens
限制模型本次最多生成多少 token。
- **对本项目**:要从上下文预算里扣除。设 800 约等于 400~500 汉字。

### finish_reason
本次生成为什么结束:`stop`(正常)/ `length`(达到 max_tokens 被截断)/ `tool_calls` / `content_filter`。
- **对本项目**:`length` 时应提供"继续"按钮;`content_filter` 要给友好提示。

### usage
响应中返回的实际 token 用量:`prompt_tokens` / `completion_tokens`。
- **对本项目**:费用统计的唯一准确来源。

## 二、做角色扮演会遇到的

### Few-shot(少样本示例)
在 Prompt 里给几个"问-答"示例,让模型模仿。
- **对本项目**:角色卡的 `example_dialogues`。**对说话风格的影响比写十条规则更大**,是最重要的字段之一。

### 角色卡(Character Card)
社区通行的角色定义格式,包含人设、开场白、示例对话等。
- **SillyTavern V2** 是事实标准,数据以 base64 JSON 藏在 PNG 的 `tEXt` chunk 里。
- **对本项目**:兼容它 = 直接继承海量现成内容。B-3 是 P0。

### Persona(人格)
两种用法:角色的人设 / 用户在故事里扮演的身份。本项目中:
- `CharacterCard.persona` = AI 扮演谁
- `Persona` 实体 = 用户扮演谁

### Lorebook / World Info(世界书)
一组"关键词 → 设定文本"的条目。对话中出现关键词时才把对应设定注入上下文,以节省 token。
- **对本项目**:B-5 / D-5。庞大世界观的标准解法。

### OOC(Out Of Character,出戏)
两个含义:
1. 贬义:AI 跳出角色说"作为 AI 我不能..." —— 需要对抗
2. 中性:用户主动发的导演指令,如 `[让场景转入夜晚]` —— 本项目的 C-8 功能

### Swipe(滑动切换候选)
对同一个用户输入生成多个 AI 回复,左右滑动挑一个。
- **对本项目**:C-4,角色扮演刚需。底层就是对话树的兄弟节点。

### 人设漂移(Character Drift)
长对话中角色逐渐失去个性、趋同为"温柔有礼的助手"。
- **对本项目**:核心质量问题。解法见 `docs/05` §5。

## 三、做游戏化会遇到的

### Function Calling / Tool Use(工具调用)
给模型一组函数定义,它可以输出"我要调用某函数 + 参数(JSON)",而不只是说话。注意:**模型并不真的执行函数,只是告诉你它想调用**,实际执行由你的代码完成。
- **对本项目**:E-2,让 AI 上报游戏状态变化的机制。

### JSON Schema
描述 JSON 结构的规范,用于定义工具参数。
- **对本项目**:根据角色卡的状态字段 **动态生成** schema。

### Structured Output(结构化输出)
让模型保证输出符合指定 JSON 格式的能力(部分服务商支持 `response_format`)。
- **对本项目**:Tool Calling 的替代方案之一。

## 四、做记忆系统会遇到的

### Embedding(嵌入 / 向量化)
把一段文本转成一个浮点数组(如 1536 维),语义相近的文本向量也相近。
- **对本项目**:D-6,语义检索记忆。P2 才做。

### 余弦相似度(Cosine Similarity)
衡量两个向量方向接近程度的指标,范围 -1~1,越大越相似。
- **对本项目**:端上做暴力检索,千级条目 < 10ms,不需要向量数据库。

### RAG(检索增强生成)
先从知识库检索相关内容,再塞进 Prompt 让模型参考。
- **对本项目**:世界书 + 记忆注入本质上就是 RAG 的简化形态。不要被这个词吓到。

### 摘要压缩(Summarization)
把一段长对话让模型总结成几句话,替代原文放进上下文。
- **对本项目**:D-3,长对话不失忆的核心手段。

## 五、看文档/选模型会遇到的

### LLM(Large Language Model,大语言模型)
就是 GPT / Claude / DeepSeek 这类模型的统称。

### 推理模型(Reasoning Model)
如 o 系列、DeepSeek-R1。会先输出一段"思考过程"再给答案,响应里有 `reasoning_content` 字段。
- **对本项目**:角色扮演一般 **不推荐**(慢、贵、文风偏理性)。但 UI 要能正确处理这个字段,不要把思考过程当正文显示。

### 对齐(Alignment)/ 安全对齐
模型被训练得"有帮助、无害、诚实"。
- **对本项目**:这是"AI 过度顺从、不愿演反派、容易出戏"的根源。不同模型的对齐强度差异很大,这是选模型的关键维度。

### 微调(Fine-tuning)
用自己的数据继续训练模型。
- **对本项目**:**不需要,不要做**。成本高、收益低,Prompt 工程足以解决。

### 蒸馏 / 量化 / 参数量(7B/70B)
模型大小与压缩相关概念。
- **对本项目**:只在考虑本地模型(Ollama)时需要了解。用户的事,不是我们的事。

### 上下文缓存(Prompt Caching)
部分服务商对重复的前缀 Prompt 提供折扣(如 Claude、DeepSeek)。
- **对本项目**:把 **固定内容放在前面、变化内容放在后面** 能省不少钱。这是 `ContextBuilder` 块顺序设计的一个隐藏收益。

### 幻觉(Hallucination)
模型自信地编造不存在的事实。
- **对本项目**:在叙事里这叫"创意",在数值里这叫"bug"。这就是为什么状态必须由客户端管。

### 越狱(Jailbreak)
用特殊 Prompt 绕过模型的安全限制。
- **对本项目**:**我们不提供、不内置、不推荐**。见 `docs/07` §4.3。这是法律责任的分界线。

---

## 六、一句话记住本项目的核心认知

> **模型是一个没有记忆、不会算数、但很会写字的演员。**
> 你的 App 要当好编剧(Prompt)、提词人(记忆)、和记分员(状态机)。
